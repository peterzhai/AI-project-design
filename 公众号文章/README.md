# 《从 LLM 到 AI Agent》公众号系列 · 工作流与进度

> 机制：**项目每实现一个目标 → 对照大纲确定文章 → 按固定结构成文 → 同步编号与进度**。
> 大纲与写作规范见 `../从LLM到AI-Agent-系列大纲.md`；本目录管文章，`my-base-agent` 管实现。

## 一、目标 → 文章 流程

每完成一个项目里程碑（功能落地 / 架构决策 / 踩坑复盘），按以下步骤产出一篇文章：

1. **对照大纲**：在下方进度表找到对应条目，确认该目标已在 `my-base-agent` 中真实实现（代码 + 测试），而不是只在文档里。
2. **成文**：按"固定结构"写，文件命名 `NN-标题.md`（NN = 公众号发布序号，见下）。
3. **同步编号**：
   - 更新本文末尾进度表的"文章状态 / 发布状态"；
   - 更新 `00-学习篇章.md` 的"已发布文章"表；
   - 更新所有已发文章末尾的"系列目录"块（只列已发布篇目，标注"（本篇）"）。
4. **脱敏检查**：工厂业务数据、内网信息、客户信息一律替换为虚构示例（大纲第七节第 1 条）。

## 二、文章固定结构（每篇）

1. **发布信息块**（排版时删除）：标题候选、摘要栏、封面建议、合集标签
2. **冷启动**（约 300 字）：具体场景或翻车现场，抛出核心问题
3. **概念**（约 1000 字）：从零讲透，能用类比就用类比
4. **动手**（代码 30–80 行）：最小可运行版本，完整可复制
5. **进阶视角**（约 800 字）：真实项目怎么做的、为什么、踩过什么坑
6. **小结 + 预告**：三句话总结；下一篇的问题钩子
7. **系列目录**（持续更新）：已发布篇目列表

其他约定：每篇至少 1 张图（源文件留存）；代码统一 Python 3.12，最小代码放配套仓库；篇幅 3000–4500 字。

## 三、命名与编号规范

- 文件名：`NN-标题.md`，NN 为**公众号发布序号**（01 起递增）。
- **发布序号 ≠ 大纲条目号**：大纲是规划，发布序号是实际连载顺序。已插入过一次非大纲文章（02 什么是 LLM）。对应关系记录在 `00-学习篇章.md` 的"已发布文章"表。
- 番外/科普性质的文章若不占主线编号，用前缀区分（如 `番外-xxx.md`），并在进度表注明。
