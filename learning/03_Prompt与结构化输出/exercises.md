# 第 3 章 · 练习

## 练习 1（热身）：给工单 schema 加新字段

给 `TICKET_SCHEMA` 增加 `channel` 字段：string，枚举 `["电话", "微信", "邮件"]`，
并同步修改示例 01 的 `STRUCTURED_PROMPT` 输出契约与 few-shot 示例。

**验收标准**：
- 校验器拒绝 `channel: "飞鸽传书"`；
- 提示词里的契约、示例、schema 三处保持一致；
- 用 pytest 断言以上两点。

**参考答案要点**：
- 关键习惯：**一处修改，三处同步**（提示词契约、few-shot 示例、schema）。更好的做法是
  用代码从 schema 生成提示词里的字段说明（进阶方向，参考练习 3）。
- 枚举字段是最容易"模型即兴发挥"的地方，所以第 3 板斧示例里也要演示合法取值。

## 练习 2（进阶）：多对象输出的宽容解析

`extract_json_object` 目前只找"第一个 { 到最后一个 }"。当模型输出**数组**（如
`结果如下：[{"a":1},{"b":2}]`）时会定位失败。请写 `extract_json_array` 处理 `[` 到 `]`，
并让 `parse_llm_json` 自动判断先找对象还是先找数组（哪种括号先出现用哪种）。

**验收标准**：
- `'结果：[{"a": 1}, {"b": 2}] 完毕'` 能解析出 `list[dict]`；
- 原有对象路径的行为完全不变（回归测试）。

**参考答案要点**：
- 比较 `text.find("{")` 与 `text.find("[")` 的大小决定入口；注意嵌套括号场景
  （对象里的数组）用"首括号配对计数法"比 rfind 更稳，可作为挑战进阶。
- 记得为"对象和数组都没找到"写明确报错，别返回原文让 json.loads 给出迷惑性错误。

## 练习 3（挑战）：从 schema 自动生成提示词片段

写 `schema_to_instructions(schema) -> str`：把 JSON Schema 翻译成给模型看的中文说明，
例如 `{"type": "string", "enum": ["低", "中", "高"]}` →
`urgency: string，只能是 "低"、"中"、"高"`。

**验收标准**：
- 支持 string/integer/enum/required 四类信息的翻译；
- 生成文本直接拼进 system 提示词后，Mock 模型（handler 检查文本含 "只输出 JSON"）
  仍能给出可解析输出 —— 即**提示词与 schema 从此只有一处真相**；
- pytest 覆盖：生成文本包含字段名、类型与枚举值。

**参考答案要点**：
- 递归遍历 `properties`，按 type 分支拼说明；required 列表单独标注"必填"。
- 这消除了练习 1 指出的"三处同步"问题 —— schema 成为唯一事实来源，
  提示词由它派生。第 4 章的 ToolBox.schemas() 会用到完全相同的思路：
  **工具描述与调用协议也从同一份定义生成**。
