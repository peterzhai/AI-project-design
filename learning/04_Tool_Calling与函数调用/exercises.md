# 第 4 章 · 练习

## 练习 1（热身）：给 schema 生成器加枚举支持

`function_to_schema` 目前只支持四种基本类型。请让它支持 `typing.Literal`：
参数标注为 `Literal["低", "中", "高"]` 时，生成的属性是
`{"type": "string", "enum": ["低", "中", "高"]}`。

**验收标准**：
- 新函数 `set_urgency(level: Literal["低", "中", "高"]) -> str` 能注册并生成含 enum 的 schema；
- `ToolBox.execute` 拒绝 `level="超级紧急"`（防线 2 复用第 3 章校验器，天然支持）；
- 不带 Literal 标注的旧函数行为不变（回归测试）。

**参考答案要点**：
- `typing.get_origin(Literal[...]) is Literal` 判断，`typing.get_args` 取枚举值。
- 这打通了"第 3 章校验器 enum + 第 4 章 schema 生成"的最后一公里：
  枚举约束从 schema 一路贯通到运行时校验。

## 练习 2（进阶）：工具结果太大怎么办——结果截断器

真实工具可能返回几万字符的网页内容，直接塞回上下文会撑爆窗口、烧掉预算。
请实现 `truncate_observation(text: str, max_chars: int = 2000) -> str`：
超长时截断并附加提示（保留头尾各一半 + `"...[已截断，原文 N 字符，完整内容见 id=xxx]"`）。

**验收标准**：
- 短文本原样返回；
- 长文本头尾拼接且总长不超过 max_chars + 提示长度；
- 提示里包含原始长度数字。

**参考答案要点**：
- 截断发生在 ToolBox.execute 的出口处（对"观察"统一加工），而不是每个工具自己处理 ——
  这就是"装饰观察"模式：第 6 章记忆压缩、第 11 章脱敏都复用这个位置。
- 思考题：截断 vs 摘要（第 6 章引入 LLM 摘要）的适用边界是什么？

## 练习 3（挑战）：工具调用重试的"预算闭环"

把第 2 章的 `with_retries` 与本章 ToolBox 组合：模型给出的参数非法时，不要立刻把
错误观察回传，而是**让模型带着错误观察自己重试**，最多 2 次；2 次都失败才放弃该工具，
直接把"放弃说明"作为观察回传。

**验收标准**：
- MockLLM 脚本：第 1 次参数错、第 2 次参数对 -> 最终执行成功，共 2 轮工具消息；
- 两次都错 -> 第 3 次模型收到的观察是"放弃说明"而不是校验错误；
- pytest 断言消息条数与观察内容。

**参考答案要点**：
- 区分"应用层重试"（with_retries，针对网络/限流）与"模型层重试"（本练习，针对参数错）——
  前者不花模型调用，后者每次都花钱，所以要设预算。
- 实现位置在 run_protocol 的第 2→3 步之间：校验失败时不执行，先让模型修正参数。
- 这个"参数修正循环"正是第 5 章 ReAct 的雏形：观察（校验失败）→ 思考（怎么改）→ 再行动。
